# Statut de cette version

Nuxt 4.4 est la version stable actuelle (juin 2026) et reçoit des
correctifs réguliers (patchs hebdomadaires, mineures mensuelles d'après le
rythme habituel du projet). C'est la version de référence pour tout
nouveau projet Nuxt à partir de maintenant.

# Racine applicative

`app/` — tout le code applicatif vit ici. `server/`, `public/`,
`modules/`, `content/`, `layers/`, `shared/` et `nuxt.config.ts` restent
à la racine du projet, hors de `app/`.

# Résolution de chemins

| Élément | Chemin |
|---|---|
| Pages | `app/pages/` |
| Composants | `app/components/` |
| Composables | `app/composables/` |
| Stores Pinia | `app/stores/` |
| Middleware | `app/middleware/` |
| Plugins | `app/plugins/` |
| Layouts | `app/layouts/` |
| Types partagés (accessibles aussi côté server/) | `shared/types/` |
| Routes serveur (API) | `server/api/` (reste à la racine, hors `app/`) |
| Assets statiques publics | `public/` (reste à la racine) |
| Tests unitaires | `tests/unit/` (reste à la racine) |
| Tests e2e | `tests/e2e/` (reste à la racine) |

# Alias

`~/` et `@/` pointent vers `app/` (pas vers la racine du projet,
contrairement à Nuxt 3).

# Un seul tsconfig.json

Nuxt 4 ne génère plus qu'un seul `tsconfig.json` à la racine du projet —
fini les configurations TypeScript séparées et parfois incohérentes entre
le code app et le code serveur des anciennes versions.

# Commande de création de projet

```bash
npx nuxi@latest init mon-projet
# crée directement la structure app/ par défaut depuis Nuxt 4
```

# Piège spécifique à la migration v3 → v4

Si un fichier hors de `app/` (ex. un utilitaire partagé à la racine) est
importé via `~/`, l'import casse car `~/` ne pointe plus vers la racine.
Deux solutions :
- Déplacer le fichier dans `shared/` s'il doit être accessible à la fois
  par `app/` et `server/`.
- Utiliser un alias dédié (`@root/`) si le déplacer n'est pas souhaitable.

# Outil de migration officiel

```bash
npx codemod@latest nuxt/4/migration-recipe
```

Automatise une grande partie du déplacement de fichiers vers `app/` —
ne dispense pas de vérifier les imports relatifs cassés après coup.
