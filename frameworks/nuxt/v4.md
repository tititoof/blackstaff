# Racine applicative

`app/` — tout le code applicatif vit ici. `server/`, `public/`,
`modules/`, `content/`, `layers/`, `shared/` et `nuxt.config.ts` restent
à la racine du projet, hors de `app/`.

# Résolution de chemins

| Élément | Chemin |
|---|---|
| Pages | `app/pages/` |
| Composants | `app/components/` |
| Composables | `app/composables/` |
| Stores Pinia | `app/stores/` |
| Middleware | `app/middleware/` |
| Plugins | `app/plugins/` |
| Layouts | `app/layouts/` |
| Types partagés (accessibles aussi côté server/) | `shared/types/` |
| Routes serveur (API) | `server/api/` (reste à la racine, hors `app/`) |
| Assets statiques publics | `public/` (reste à la racine) |
| Tests unitaires | `tests/unit/` (reste à la racine) |
| Tests e2e | `tests/e2e/` (reste à la racine) |

# Alias

`~/` et `@/` pointent vers `app/` (pas vers la racine du projet,
contrairement à Nuxt 3).

# Langue des noms

Tous les noms de fichiers, dossiers, types, variables et fonctions sont
TOUJOURS en anglais — même si l'instruction ou la description de la tâche
est en français. Traduire les termes métier soi-même (ex: "recherche" →
"search", "catégorie" → "category", "utilisateur" → "user"). Aucun
caractère accentué dans un chemin de fichier ou un identifiant. Seuls les
textes visibles par l'utilisateur final (labels UI, messages d'erreur,
placeholders de formulaire) peuvent rester en français si l'application
est destinée à un public francophone.
